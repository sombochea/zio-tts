# Zio TTS v1 — Khmer text-to-speech (multi-speaker)

A small [VITS](https://arxiv.org/abs/2106.06103) model that speaks **Khmer** at 24 kHz. First research release of the [Zio](https://github.com/sombochea/zio-tts) project (Khmer + English speech, open source).

> **Status: experimental.** 16 male voices, 2.9 hours of training audio in total. Expect understandable-but-imperfect Khmer with some mispronunciations, not studio quality. **English is not supported yet** (no English audio was used). No emotion control yet. No quantitative evaluation has been done; see *Evaluation*.
>
> **v0 → v1:** v0 was one speaker with only 46 minutes of audio, and sounded poor. v1 trains one model on all 16 speakers (2.9 h) so pronunciation is learned from 3.8× more data; the voice is selected by id.

Samples: [`samples/`](samples) (generated by this exact checkpoint).

## Get started

Fastest path (3 commands, needs [`uv`](https://docs.astral.sh/uv/) and ffmpeg):
```bash
uv tool install huggingface_hub                       # provides the `hf` CLI
hf download {{REPO}} --local-dir zio-tts              # private repo? run `hf auth login` first
git clone https://github.com/sombochea/zio-tts && cd zio-tts && uv sync --extra tts && uv run zio speak "សួស្តី" hello.wav --run ../zio-tts
```
Details below.

### 1. Python / CLI (recommended)
```bash
git clone https://github.com/sombochea/zio-tts && cd zio-tts
uv sync --extra tts                      # needs Python 3.12+ and ffmpeg
hf download {{REPO}} --local-dir zio-tts
uv run zio speak "សួស្តី តើអ្នកសុខសប្បាយជាទេ" hello.wav --run zio-tts
uv run zio speak "សួស្តី" other.wav --run zio-tts --voice km_7548__neutral     # pick another voice
```
Voices are named `<speaker>__neutral` (the `__neutral` suffix is the emotion slot; only neutral exists so far). `km_6753__neutral` has the most training data and is the default. All voice names are in `vocab.json` (`voices`).
Or from Python:
```python
from zio.tts.infer import synthesize
synthesize("zio-tts", "ថ្ងៃនេះអាកាសធាតុល្អណាស់", "out.wav", voice="km_6753__neutral")
```
Text is normalized (Khmer digits and `៛`/`$` become spoken words) and word-segmented automatically — the model was trained on **word-spaced** Khmer, so unsegmented text sounds worse.

### 2. ONNX (no PyTorch)
`zio-tts.onnx` + `vocab.json` are included.
```bash
pip install onnxruntime soundfile "zio @ git+https://github.com/sombochea/zio-tts"
python examples/onnx_infer.py zio-tts.onnx vocab.json "សួស្តី" out.wav km_6753__neutral
```
Inputs: `input` (int64 token ids), `input_lengths`, `scales = [noise 0.667, length 1.0, noise_dp 0.8]`, `sid` (int64 speaker id from `vocab.json` → `voices`). Token ids = the `vocab.json` id of each character with `blank_id` between every character. Larger `length` scale = slower speech.

## Model details
| | |
|---|---|
| Architecture | VITS (coqui-tts), graphemes (Khmer characters + a–z), no phonemizer |
| Sample rate | 24 kHz mono |
| Voices | 16 speakers (SLR42 male subset), one learned embedding each |
| Training data | 2,906 utterances ≈ 2.9 h of [OpenSLR SLR42](https://openslr.org/42/) (Google, CC BY-SA 4.0); the largest speaker has 46 min, the smallest 4 min |
| Training | Started from scratch on an A100 (Modal), continued on a free Kaggle GPU; best checkpoint by eval loss. The exact epoch/step is in the *Checkpoint* note below the card, if present |
| Files | `best_model.pth`, `config.json`, `speakers.pth` (coqui), `zio-tts.onnx`, `vocab.json` |

Why graphemes: espeak-ng has no Khmer voice, so no off-the-shelf G2P exists. A Khmer G2P is future work.

## Limitations
- Khmer only; male voices only (the public SLR42 subset we have); no emotion/style control; no voice cloning. Small speakers (4–10 min) sound worse than `km_6753`.
- Under 3 h of data → mispronunciations, unstable prosody on long or rare words. Keep sentences short (< ~15 s).
- Numbers are read via simple rules up to 999,999,999; dates, units, abbreviations and mixed Khmer/English text are not handled.
- Not suitable for impersonating anyone. Please disclose that the speech is synthetic.

## Evaluation
None yet: no MOS, no intelligibility CER. Treat quality claims as unverified until the project publishes numbers.
